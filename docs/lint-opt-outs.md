# Lint opt-outs

Every Oxlint category is `"error"` in `.oxlintrc.json`, and every Oxlint plugin for the stack is on ([ADR 0012](adr/0012-lint-opt-outs.md)). A rule is off or loosened only for a contradiction: two rules that can't both pass, a rule that fights the cookout's layout, or a false positive on a library's documented API. A rule that is only harsh stays on. This file lists every opt-out with its reason. A commit that turns a rule off or loosens it adds its entry here, with the reason, in the same commit.

## Off everywhere

- `import/no-named-export`, `import/prefer-default-export`: contradict `import/no-default-export`. Entry points use named exports.
- `import/group-exports`: one export statement per file leaves no place for the JSDoc block on each exported function that `local/no-comments` allows.
- `import/no-relative-parent-imports`: `tests/` and `lib/` reach their module's entry points through `../`. dependency-cruiser owns import shape.
- `vitest/no-importing-vitest-globals`: contradicts `vitest/prefer-importing-vitest-globals`, and `@effect/vitest` must be imported.
- `vitest/require-top-level-describe`: contradicts the `describe` ban (`vitest/max-nested-describe` at `max: 0`).
- `react/react-in-jsx-scope`: obsolete under the automatic JSX runtime (`jsx: react-jsx`).
- `unicorn/throw-new-error`: fires on Effect's `Schema.TaggedError<Self>()(...)` class factory, whose instances `effecttsgo/new-schema-class` says to build with `make`.
- `jsdoc/require-param-type`, `jsdoc/require-property-type`, `jsdoc/require-returns-type`: types live in TypeScript. `eslint-plugin-jsdoc`'s own `recommended-typescript` config turns these off.
- `no-undef`, `no-redeclare`: `tsc` checks both, and typescript-eslint's `eslint-recommended` config turns them off. `no-redeclare` also fires on a value and a type sharing a name, which is Effect's `Schema` idiom.
- `oxc/no-async-await`: a function that returns a Promise fails `typescript/promise-function-async` unless it is `async`, and a `.then` chain fails `promise/prefer-await-to-then`. The SDK is plain TypeScript and returns Promises. Backend code still can't be `async`: `effecttsgo/async-function` bans it there.
- `oxc/no-rest-spread-properties`: copying an object with one field changed is either `{ ...object, field }`, which it bans, or `Object.assign({}, object, { field })`, which `prefer-object-spread` bans. Like `oxc/no-async-await`, it guards against engines older than the ES2024 target.
- `vitest/prefer-to-be-truthy`, `vitest/prefer-to-be-falsy`: contradict `vitest/prefer-strict-boolean-matchers`. The strict matcher stays, since it fails on a value that is only truthy.
- `unicorn/no-null`: the wire protocol and SQLite need `null`. A top-level message's `latestReplyId` is `null` until it has a reply, a message's `data` may be JSON `null`, which must stay apart from no data, and `node:sqlite` binds `null` as SQL `NULL` and rejects `undefined`. The modules that need it give no clean scope. Code that means "nothing here" still uses `undefined` or `Option`.
- `sort-imports`: `local/sort-imports` (`lint/rules/sort-imports.js`) checks the same thing and also fixes the order of the import declarations, which the native rule can't. Biome's `organizeImports` stays off too, since it sorts by module path and the two would undo each other.

## Off in some files

- The 15 `effecttsgo` rules that name a global or a Node API (`async-function`, `crypto-random-uuid`, `extends-native-error`, `global-console`, `global-date`, `global-fetch`, `global-json`, `global-random`, `global-timers`, `new-promise`, `node-builtin-import`, `prefer-effect-array`, `prefer-effect-record`, `prefer-effect-string`, `process-env`), in every `app/` file outside backend code (`server.ts`, `lib/server/`, `tests/`) and in `app/web.tsx`. They point at Effect APIs, which those files may not import. The `no-restricted-globals` owners still apply there.
- `no-restricted-globals` lets `app/modules/format/` use `Date` and `setInterval`: it is the web UI's one reader of the time and its one clock, which ticks a time shown as how long ago (mattpocock/cookout#153). Every other web module reads the time and ticks only through it.
- `effecttsgo/node-builtin-import` and `import/no-nodejs-modules`, in the owner adapters of a Node API: `http`'s server (`node:http`), the storage SQLite adapter (`node:sqlite`) and the secrets Layer (`node:crypto`). Each one is the single owner of that API, and the other files stay banned from it by `no-restricted-imports`.
- `no-restricted-globals` lets `app/modules/format/` read `Date` ([#134](https://github.com/mattpocock/cookout/issues/134)): the web UI writes message times in the person's own time zone, which needs `Date` in the browser, and Effect's Clock is for the backend. Every other file stays banned from it. Confirmed by Matt, 2026-11-23.
- `effecttsgo/node-builtin-import` and `import/no-nodejs-modules`, in `app/modules/cli/lib/server/adapters/machine.ts` ([#117](https://github.com/mattpocock/cookout/issues/117)): it imports `node:os` for the machine's name, as the one owner of that API. Confirmed by Matt, 2026-11-23.
- `effecttsgo/process-env` and `node/no-process-env`, in `config`: it is the one reader of `process.env`.
- `effecttsgo/strict-effect-provide`, in `app/main.ts`, where the live Layers are provided. Also in tests: each test is its own application root and provides its own Layer.
- `jsx-a11y/prefer-tag-over-role`, in `app/modules/design-system/lib/panel-edge.tsx`: a panel's draggable edge is a focusable `role="separator"` (the WAI-ARIA window splitter), which takes keys and a pointer. The rule asks for `<hr>` instead, but `jsx-a11y/no-noninteractive-tabindex` and `jsx-a11y/no-noninteractive-element-interactions` then refuse an `<hr>` that is focusable and has handlers, so the three can't all pass (#315).
- `jsx-a11y/prefer-tag-over-role`, in `app/modules/design-system/lib/listbox.tsx`: the message box's `@` and `/` suggestion lists (#429) and the search box's results (#425) are both a WAI-ARIA combobox's `role="listbox"`, which holds `role="option"`s, in named `role="group"`s for the search box, named by the box's `aria-activedescendant` while focus stays in the box. `Listbox` is the one component that draws those roles, so both lists use it (#449). The rule asks for `<select>` or `<datalist>`, `<optgroup>` and `<option>`, which can't hold a presence dot, a muted detail or a message's highlighted text, and can't be driven from a text box that keeps the focus.
- `vitest/require-hook`, outside `*.test.*` files: it flags every top-level statement, which is a false positive in a program entry or a script that runs at the top level. In tests it stays on and bans a top-level `layer(...)`.
- `import/no-default-export`, in `vitest.config.ts` and `tsdown.config.ts`: Vitest and tsdown read their config from the file's default export. Also in `scripts/web-test-environment.ts`, since Vitest reads a custom environment from its default export, and in `lint/test-rules.js`, `lint/web-rules.js` and `lint/export-rules.js`, since oxlint reads a JS plugin from its default export.
- `typescript/no-unsafe-*`, in `lint/**/*.js` and `*.cjs`: they are untyped JavaScript (the Oxlint JS plugin API and dependency-cruiser's config format), so every value is `any`.
- `scripts/`, `lint/`, `*.cjs`, `vitest.config.ts` and `tsdown.config.ts` are Node tooling outside `app/`, not backend code. In them the same 15 `effecttsgo` rules are off, plus `import/no-nodejs-modules` and `no-console`. The local rules in `lint/rules/` run inside Oxlint's JS plugin host, which calls plain synchronous visitors, so Effect can't be their implementation. The scripts run directly under `node` from Lefthook and CI. Written in Effect, each one would have to run its own effects, which `no-restricted-properties` bans outside `app/main.ts`. Their job is to print a report and spawn tools, as the existing override that lifts `no-restricted-globals` and `no-restricted-imports` there already says. Every other rule still applies to them, ratcheted like the rest.
- `unicorn/no-array-method-this-argument`, in backend code: it reads every two-argument `map` or `forEach` call as an array method given a `thisArg`, so it fails Effect's `Effect.forEach(items, f, { concurrency })`, `Effect.map(effect, f)` and `Array.map(items, f)`, which `effecttsgo/prefer-effect-array` asks for.
- `node/no-sync`, `node/no-top-level-await`, in `scripts/` and `lint/`: a script entry must use the sync file APIs, a top-level `await` or a floating Promise, and `unicorn/prefer-top-level-await` asks for the top-level `await` that `node/no-top-level-await` bans. The local rules in `lint/rules/` run inside Oxlint's JS plugin host, which calls synchronous visitors.
- `effecttsgo/api-stability-leak`, in `cli`, `storage`, `testing`, `dev`, `http/server.ts`, `limits/server.ts` and the packages' modules that require the platform: their interfaces require `FileSystem`, `Path`, `ChildProcessSpawner` or `effect/http` types, which Effect marks unstable, so the rule would leave only hiding the requirement in a Layer built in place. The rule guards the importers of a published package, and the only published surface is the SDK, which `published-sdk-reaches-no-effect` keeps free of Effect, and the binary, which has no importers.

## Loosened

- `func-style`: `"declaration"`, to agree with `react/function-component-definition`.
- `no-duplicate-imports`: `allowSeparateTypeImports`, to agree with `import/consistent-type-specifier-style`.
- `new-cap`: `properties: false`, since Effect's API is capitalized namespace functions (`Schema.Struct`, `Context.Service`).
- `react/jsx-filename-extension`: `.tsx` only, the extension the layout uses.
- `vitest/no-standalone-expect`: `@effect/vitest`'s `it.effect`, `it.effect.each`, `it.live` and `it.prop` count as test blocks.
- `vitest/consistent-test-it`: `it`, inside and outside `describe`. `@effect/vitest` exports `it` (with `it.effect`) and no `test`. The default (`test`) has a fix that renames `it` to `test` without an import, which breaks `tsc`.
- `typescript/prefer-readonly-parameter-types`: allows `@effect/vitest`'s `Methods` and `MethodsNonLive`, the mutable `it` its callbacks receive.
- `typescript/prefer-readonly-parameter-types`: allows the standard library's `Uint8Array`, which has no readonly form, so no function could take an attachment's bytes (#373).
- `typescript/prefer-readonly-parameter-types`: allows React's `ChangeEvent`, `ClipboardEvent`, `DragEvent`, `KeyboardEvent` and `MouseEvent`, which a handler receives as React makes them and can't mark readonly (`SidebarBody` reads a click's target, #144; the message box reads pasted, dropped and picked files, #377).
- `effecttsgo/unstable-api-usage`: `allowedUnstableApis` in the `@effect/language-service` entry of `tsconfig.json` holds `@effect/vitest`, which the tests use, `effect/testing/TestConsole`, which `testing` captures a command line's output with, and the unstable Effect 4 modules the cookout is built on: `effect/cli`, `effect/http`, `effect/process`, `effect/FileSystem`, `effect/Path`, `effect/ByteSize`, `effect/Stdio` (which `cookout login --token` reads the token from, #115), `@effect/platform-node`, and `@effect/platform-node-shared/NodeSocket`, which `@effect/platform-node`'s `NodeSocket` re-exports and the reporter names in its place (a test opens a raw TCP connection with it, #130), and the Postgres client the storage Postgres adapter is built on (#330): `@effect/sql-pg`, the `effect/sql` modules it implements (`SqlClient`, `SqlError`), and `effect/reactivity/Reactivity`, the service its client needs.
- `effecttsgo/deterministic-keys`: `keyPatterns` skips the leading `app/modules/` of a file path, so a key derives from the module path.
- `typescript/promise-function-async`: `checkArrowFunctions: false` in backend code. There the only Promise-returning functions are the arrows handed to `Effect.promise` and `Effect.tryPromise`, and `effecttsgo/async-function` bans the `async` the rule asks for.
- `one-var`: `"never"`. With `"always"`, `sort-vars` sorts a scope's one `const` statement by name, so a declarator that uses one declared later in the alphabet is a use before definition, and nothing can be bound after a statement in `Effect.gen`.
- `typescript/prefer-readonly-parameter-types`: `treatMethodsAsReadonly`, and Effect's `Effect`, `Layer`, `Stream`, `Schema.Constraint`, `Exit`, `Option`, `DateTime` (`Utc`, `Zoned`), `HttpClientRequest`, `HttpClientResponse` and `HttpServerResponse` allowed. Effect's values are immutable, but their interfaces declare `pipe` as a method and carry internals the rule reads as mutable, so no function could take one as a parameter.
- `vitest/require-hook`: `allowedFunctionCalls: ["ruleTester.run"]`. Oxlint's `RuleTester` registers its tests only from a top-level call, so no rule suite in `lint/tests/` could pass otherwise.

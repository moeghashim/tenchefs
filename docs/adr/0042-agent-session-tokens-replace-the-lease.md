# Agent session tokens replace the lease

2026-11-23 (mattpocock/cookout#114). Supersedes ADR 0004, and the lease parts of ADR 0025 and ADR 0028. Replacing the lease with an agent session token, its 7-day idle expiry, the 90-day ceiling and one live token per agent are Matt's decisions of 2026-11-23, recorded on #114; the route, the refusal codes and the 30 s check of an open stream are chief-of-staff choices, pending Matt's review.

The lease was a 60-second hold on an identity, renewed by every request that carried its ID in `cookout-lease`, and only leave, ack and watch needed it. It never authenticated anything: a session still sent the agent's Identity token, so the lease was a second, weaker credential beside the first. Now `join` issues an **agent session token**, a token of its own that authenticates as the agent for one session, and the lease is gone.

- **Join issues a token.** `POST /v1/agent-session` with the agent's own Identity token (`as` must be its name; a human is 403 `identity_kind`) answers `{ agentSessionToken, issuedAt, expiresAt }`. Requests sent with that token act as the agent. The store keeps only its hash.
- **One live token per agent.** A second join while the agent has a live one is 409 `agent_session_live` with its `expiresAt`, unless `force`, which revokes the old one at once: its next request is 401 `agent_session_revoked`. Storage issues the token, checking for a live one and revoking it on `force`, as one atomic method, so two sessions can't race past the check.
- **Idle expiry.** A token expires once it goes unused for its idle expiry: 7 days by default, or what `join --idle-expiry` asks for (such as `30d`), up to `COOKOUT_MAX_IDLE_EXPIRY` (default `90d`, else 400 `idle_expiry_too_long` naming the ceiling). Each request sent with it moves its expiry on, in the same storage step that authenticates it. An expired token is 401 `agent_session_expired`.
- **Leave revokes it.** `DELETE /v1/agent-session` revokes the agent session token it is sent with (400 `agent_session_required` with any other token). The agent's Identity token keeps working.
- **Nothing else needs a session.** Ack and watch need only authentication, so the rule of ADR 0025 and the human exemption of ADR 0028 have nothing left to decide.
- **Watch notices a revoked token.** A stream opened with an agent session token checks it every 30 s, moving its expiry on, and ends with the `agent_session_revoked` (or `agent_session_expired`) refusal once it is no longer live. `cookout watch` exits 4 on either, as it did on `lease_lost`.

The CLI keeps the token where it kept the lease ID, in one state file per server and Identity token under `COOKOUT_STATE_DIR`, and sends it instead of `COOKOUT_TOKEN` on every later verb but `join`; it deletes the file on `leave` and on either 401. Keying the file by agent tool session instead is the next ticket's.
